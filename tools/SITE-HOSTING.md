## 排查访问失败

```sh
python3 tools/check-site.py --rounds 5
```

脚本不自动重试，每次输出实际 IP、HTTP 状态、DNS/TCP/TLS/首字节累计耗时；任何失败均返回非零退出码。它检查首页、两种语言的下载页和 Mac 更新订阅。单机通过不能替代跨运营商检测。

```sh
dig +noall +answer wfdb.cc A @1.1.1.1
dig +noall +answer wfdb.cc AAAA @1.1.1.1
curl -I --connect-timeout 8 --max-time 15 https://wfdb.cc/en/downloads/
```

2026-11-15 的公网探测在旧 Cloudflare 地址上复现了福州联通 `ECONNRESET`、武汉超时，以及上海数秒的响应延迟。其他设备与网络也受影响，不能仅归因于本机 VPN。迁移期间要按探测结果中的实际 IP 区分新旧入口，避免把未过期 DNS 缓存的结果误认为新线路故障。重试成功也不能抹去首次连接失败的证据。

## 回退

GitHub Pages 配置及 `docs/CNAME` 保留。回退前先用 `curl --resolve` 核对旧 GitHub 源站内容和主域证书，不能假设它的证书会在 DNS 离开后一直有效。

原主域记录为 `185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153` 四条已代理 A 记录；原 `www` 为已代理 `192.0.2.1`，由 Cloudflare 301 规则跳转到主域。需要回退时恢复这些记录与代理状态，清楚说明旧线路的已知可达性问题仍可能复现。旧地址和回退信息已同时写入 DNS 记录备注。
